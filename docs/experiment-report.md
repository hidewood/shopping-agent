# 实验报告：可靠购物 Agent

## 问题与方法

目标是在有限本地目录中完成自然语言选购，同时避免模型虚构商品或篡改已确认条件。系统采用单一 TurnPlan：DeepSeek 只进行语义归一化和受限规划，Python 执行 schema/语义校验、事件归约、目录接地、硬过滤和确定性排序。默认链路不使用 RAG、ReAct、多 Agent 或默认 Tool Calling；`run_turn_with_tools()` 仅保留为非默认实验接口。

## 架构与工程边界

Vue 负责交互与游客令牌传递；FastAPI 提供认证和业务 API；`ShoppingAgent` 处理可验证决策；SQLite 持久化账户和业务状态；`products.jsonl` 是唯一商品事实源。当前目录含 **1,740** 件商品：`mug` 870、`shirt` 870。账户、购物车和订单为本地模拟，不代表支付或履约能力。

## 工作流与状态机

工作流先检查输入完整性与高置信意图；未命中的请求只调用一次 DeepSeek。计划不合法时可修复一次且不写入状态，仍失败返回服务错误。selection 路径从 `collecting` 进入 `exploring`、`recommended` 或 `no_match`；`merge`、`replace`、`clear` 均可通过事件日志重放。组合需求在预算/数量澄清后按逐项或合计预算计算，完成后清理临时上下文。模型失败撤销本轮约束更新，保留先前有效状态。

## 实验设计与结果记录

本地离线验收覆盖状态替换、只读隔离、非法计划无写入、目录接地、无结果放宽、组合预算和熔断。接口、前端单测和浏览器路径分别验证协议、组件和真实用户路径。发布前的真实模型集包含 48 场景（中英文、多轮、注入、异常恢复等）与 50 条公开任务；检查响应类型、Trace、目录事实、硬约束和状态变化，而不比较回复措辞。

任何结果都必须注明日期、提交号、模型和环境。现有历史结论只能标为历史，不能当作本次验收；本次文档改版未调用付费 API，因此不报告新的真实模型通过率。本地生成的 JSON 报告是唯一数值依据，不提交到 GitHub。

## 失败闭环、局限与复现

失败首先归类为模型、协议、状态、目录、API 或 UI，再以最小测试固定。模型输出受到网络、限流和版本波动影响；有限目录限制了概念映射；组合搜索在大候选空间使用有界策略；真实交易、库存、物流与生产可观测性不在当前范围。复现命令见 [README](../README.md) 与 [测试验收手册](test-report.md)。
