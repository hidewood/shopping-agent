# 测试验收手册

本文件是仓库唯一测试文档。判定依据是目录事实、硬约束、计划版本、账户数据和 API 契约，不比较模型回复措辞。测试代码、密钥和报告只留本地。

## 验收层级

| 层级 | 必查内容 |
| --- | --- |
| 语义协议 | 有序子句、原文证据、数量合计、未知概念、一次无副作用修复 |
| 状态与检索 | 单一 PurchasePlan、局部修改、只读隔离、目录接地、组合预算、结果快照 |
| API 与事务 | 401/403/404、游客令牌、revision 冲突、消息幂等、账户副作用原子提交 |
| Web | 超时进度、取消/重试、会话恢复、商品卡、收藏/购物车/订单、管理端权限 |
| 真实 DeepSeek | 自然语言、多轮、复合动作、波动与失败恢复 |

环境使用 `DEEPSEEK_THINKING_ENABLED=false`、`DEEPSEEK_MAX_RETRIES=0`、`DEEPSEEK_TIMEOUT_SECONDS=30`。发布前固定模型连续执行三轮：关键场景须 3/3，全量语义通过率至少 95%，不得虚构商品、违反硬约束或误改计划。记录日期、提交号、模型、p50/p95、会话 ID、商品 ID 和脱敏 Trace。

## M01 游客：打断、未知概念与局部恢复

1. 游客新会话输入：`你好，今天外面热不热？`。应说明能力边界，不能编造天气，也不产生采购计划。
2. 输入：`先给我看看马克杯吧，我想送人。`；再问：`你们有多少种主题，价格大概多少？`。第二句是只读查询，不应消费或覆盖前一计划。
3. 输入：`给朋友挑一个动画风的，20美元以内。`。目录没有可核验标签时必须澄清，不能把“动画”猜成相近主题，也不能写入半成品计划。
4. 输入：`那改成 Forest，预算不变，直接推荐。`。商品必须是 `mug`、含 `Forest`、价格不高于 $20。刷新页面后消息和卡片仍存在；游客收藏应提示登录。

## M02 登录用户：多人多件、复合动作与原子性

1. 登录后输入：`我想买5件T恤和3个马克杯。弟弟的3件要 Ocean，我自己的2件偏好 Nature；3个杯子都要 Nature。请各自挑合适的款，最后算总价。`。
2. 应生成三个条目，数量为 3/2/3；类型、对象、硬条件正确；不同条目尽量不重复主商品；总价严格等于快照中单价乘数量之和。
3. 输入：`弟弟那组改成 Forest，我自己的不限预算；先比较新的结果，再把最便宜的加入购物车并收藏。`。只能修改目标条目；“不限预算”只清预算；比较完成后动作引用本轮结果。
4. 在购物车调整数量并创建模拟订单。快速双击或网络重试只产生一个订单，且购物车清空与订单创建同时成功。聊天收藏必须同步出现在收藏页。
5. 输入：`这套一共多少钱？`，计划版本不得改变。再输入：`同事也要一件T恤，没风格偏好，总预算控制在60以内，重新搭配。`，应新增条目并按合计预算求解。

## M03 管理员：认证、目录和订单状态

1. 使用 `.env` 中全新管理员邮箱登录，应进入管理中心；普通用户直接访问 `/admin` 应重定向，管理 API 返回 403。公开注册管理员邮箱不能获得管理员角色。
2. 查看用户、商品和订单三个页面。新增 `Manual QA Shirt`（`shirt`、`Forest`、$19.99），在商品库可搜索；改为 $18.99 后刷新生效；删除后不可再查。
3. 普通用户创建模拟订单；管理员只能按 `confirmed → shipped → delivered` 推进。普通用户界面/API 不应提供发货或送达入口。
4. 删除或修改目录后，旧推荐快照不得被当作新目录事实；下一轮应重新检索。

## M04 复杂自然语言场景

以下场景用真实口语，覆盖复杂约束、多轮状态演变、中英混、否定/极端/自纠与不可名状主题，验证「语义编译 + 接地 + 状态机」在非规整输入下的表现。

### 复杂单句

| 编号 | 输入 | 验证点 |
| --- | --- | --- |
| C1 | 我想给女朋友买个生日礼物，她比较文艺，喜欢那种小清新的马克杯，预算别太贵，一百块以内就行 | 送礼 + 收礼人 + 小清新→Nature + 「一百块」CNY 诚实澄清 |
| C2 | 有没有那种，海洋主题、最好还带点沙滩感觉的马克杯，20 块左右 | Ocean/Beach OR 叠加 + 约数 |
| C3 | 帮我挑件 T 恤，复古的或者小清新的都行，颜色无所谓，20 刀以内 | 「A 或 B」= OR + 「无所谓」忽略维度 |
| C4 | I want a mug, but not the ocean-themed ones, under 15 dollars | 否定约束 + 英文 + 预算 |

### 多轮复杂对话

- **C5 完整送礼链路**：① 我想送人个礼物 → ② 马克杯吧 → ③ 海洋主题的，预算 20 以内 → ④ 帮我推荐一个 → ⑤ 收藏它，再加购物车。验证送礼→类型→约束→推荐→连续账户动作。
- **C6 反复改类型**：① 我想买件 T 恤 → ② 算了，还是马克杯吧 → ③ 不对，还是要 T 恤，复古风。验证类型反复切换、历史不残留。
- **C7 预算压到底再放宽**：① Ocean 主题马克杯，预算 30 以内 → ② 太贵了，20 以内 → ③ 还是贵，10 以内 → ④ 最便宜的多少钱？ → ⑤ 那放宽到 10，给我推荐一个。验证预算递减→无结果→查价→放宽恢复。
- **C8 只读打断恢复**：① 我想买个马克杯，送人的 → ② 你们一共有多少种主题？ → ③ 海洋主题的，20 以内，推荐一个。验证只读查询不破坏选购。

### 真实口语

- **C9** 就……帮我随便看看杯子吧，我最近心情不好，想买个能让人开心的那种 → 极模糊，应引导不硬推。
- **C10** ① 推荐一个海洋马克杯 → ② 上次你推荐的那个还不错，再给我来一个类似的 → 指代上轮结果。
- **C11** ① 帮我挑个马克杯，20 以内 → ② 这个太贵了吧，有没有便宜点的？差不多就行 → 模糊预算。

### 混合语言

- **C12** find me a shirt，复古风，budget 20 块 → 复古→Vintage。
- **C13** 给我看看 mug，二十美元以内，ocean 主题的。
- **C14** I'm looking for a gift for my mom, she likes vintage style, maybe under $25.

### 边界 / 异常

| 编号 | 输入 | 验证点 |
| --- | --- | --- |
| C15 | 不要海洋的，也不要复古的，随便来个便宜的马克杯 | 双重否定 + 开放 |
| C16 | 我要 20 个马克杯 | 数量上限 1–20 |
| C17 | 要蓝色的，哦不对，海洋主题的吧 | 自纠，取最后意图 |
| C18 | 有没有那种……我说不上来，反正就是很小清新的感觉 | 不可名状主题 → 澄清/映射，不硬猜 |
| C19 | 比较一下 P0005 和 P0011，然后把便宜的那个加购物车 | 复合子句 result_reference |
| C20 | ① 马克杯和 T 恤各一件，送人，总预算 30 以内 → ② 马克杯要海洋的，T 恤要复古的 → ③ 去掉 T 恤吧 → ④ 那一共多少钱？ | 组合→逐项→删行→总价 |

## 失败分诊

按 `model`、`protocol`、`state`、`catalog`、`transaction/API`、`UI` 六类记录。模型失败必须零写入；409 应自动刷新并以原消息 ID 重放；401 应清理失效登录态；未知目录概念应澄清。先保存最小自然语言复现、计划/目录版本和 Trace，再决定修协议、归约器或界面，避免为单句增加硬编码分支。

## 测试结果汇总

最近一轮完整测试（`agent-v2`，DeepSeek V4 Pro，关思考模式）覆盖约 **176 个测试点**，分四层：

| 层 | 内容 | 结果 |
| --- | --- | --- |
| L1 对话 | 71 条 A-O 矩阵 + 40 条边界扫描 + 10 组多轮对话（真实 DeepSeek） | ✅ 通过 |
| L2 账户 + 持久化 | 写读全链路、幂等/乐观并发、会话存/取/删（真实 SQLite） | ✅ 通过 |
| L3 HTTP 端点 | 认证/购物车/订单/收藏/管理员/会话/商品/健康（含 401/403/JWT） | ✅ 通过 |
| L4 管理员 | 商品 CRUD、订单状态流转 | ✅ 通过 |

### 实测发现并修复的缺陷（14 处，均在「模型输出 vs Python 编译」边界）

货币误判、目录 list 无文案、能力介绍堆砌、空消息报错、「推荐三款」、别名覆盖不足、「送人的」当名字、主题数量误判、组合后下单解析失败、Strawberry→Strawberries 名称匹配、账户只能写不能读、换一批不换商品、支付被当订单、回复机械——全部修复，详见[实验报告](experiment-report.md) §9.2。

### 已知局限（2 处）

- 小数数量（「1.5 个」）、超长主题词——模型解析层直接忽略，prompt 规则拉不回，真实用户几乎不会触发。
