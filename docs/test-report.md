# 测试验收手册

本项目以“模型理解、代码裁决”为原则：对话措辞可以变化，但目录事实、硬约束、状态和 API 契约必须可复现。目录固定为 **1,740** 件商品（`mug` 870、`shirt` 870）。

## 本地测试范围

| 层级 | 范围 |
| --- | --- |
| 离线 Python | TurnPlan、事件重放、接地、组合预算、熔断 |
| HTTP 契约 | 认证、商品/分面、收藏、购物车、订单、管理端 |
| 前端单测 | store、路由守卫、失败提示、组件交互 |
| 浏览器 E2E | 游客聊天、多轮筛选、登录与业务恢复 |
| 真实模型 | 48 个黄金场景 + 50 条公开任务 |

测试脚本、配置、依赖清单和运行产物只保留在开发者本地，均不提交到 GitHub；本文件是仓库中唯一保留的测试文档。测试 app factory 注入独立 SQLite 与本地状态；测试不得写入 `local_state/`。语义化 ID 使用 `L01`–`L48`（真实黄金集）和测试函数名表达契约。

## 访问与状态验收

游客新建会话会返回 `conversation_access_token`，后续读写须携带 `X-Conversation-Token`。登录会话仅所有者或管理员可读写。无认证、越权、令牌错误、资源不存在分别断言 401、403、403、404。只读 catalog/detail/comparison 不得覆盖活动选购状态；非法计划不得产生写入。

## 真实 DeepSeek 本地验收

真实模型仅在本地、发布前按固定模型连续运行三轮。关键场景须 3/3 通过；全量通过率须至少 95%，且不得出现虚构商品、硬约束违规或错误改写选购状态。记录提交号、模型、时间、p50/p95、失败分类及脱敏 Trace；不得以额外重试掩盖波动。

## 人工验收与失败分诊

提交前由开发者手动完成离线、接口、前端、浏览器和真实模型验收。首轮记录覆盖率基线；其后不得下降，业务变更覆盖率目标为 85% 以上。失败按 `model`、`protocol`、`state`、`catalog`、`API`、`UI` 分类，并在本地补最小回归用例。人工验收记录输入、商品 ID、条件、截图和 Trace，不以回复文案判定通过。
