# 智能购物 Agent 测试报告

## 1. 测试目标与范围

测试验证系统能否正确理解中英文购物表达、维护多轮选购状态，并且只基于 `products.jsonl` 中的真实商品信息返回目录查询、详情、比较或推荐结果。重点核验以下风险点：

- 推荐、目录查询、商品详情/比较和交易请求是否被正确路由；
- 补充条件是否合并，切换商品类型是否替换旧条件；
- 商品类型、预算、明确主题和明确厂商是否作为硬约束；
- “优先”条件是否只参与排序，而不会错误造成零结果；
- 模型服务异常、未知条件、无效商品 ID 和未实现交易动作是否诚实失败；
- 中英文价格区间及其在多轮对话中的状态迁移是否正确。

商品库包含 1,740 件商品：`mug` 与 `shirt` 各 870 件。除特别说明外，人工用例均应从“新建对话”开始；英文用例与相邻中文用例语义等价。

```bash

```

## 4. 通过标准与缺陷记录

单个用例需同时满足以下条件才判定通过：

1. **路由正确**：查询、推荐、详情、比较和交易请求不互相误判；
2. **状态正确**：补充条件合并、切换类型替换、只读查询不污染选购状态；
3. **事实正确**：展示商品存在于 `products.jsonl`，并满足全部明确硬条件；
4. **对话自然**：用户可用自由文本逐步补充，无需一次填完所有字段；
5. **边界诚实**：零结果、未知条件、服务失败和未实现交易能力不伪造成功。

出现问题时，应保存完整对话顺序、截图、推荐商品 ID，以及“核验依据”中的 Trace。Trace 可用于区分问题发生在模型规划、状态归约、目录接地、排序还是 UI 展示。
